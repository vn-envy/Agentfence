**agentfence 0.1.0** is the first release. It takes six rules for keeping a personal AI agent inside the lines and makes them into code you can drop into your own harness. One Python package, no dependencies, macOS and Linux.

## Highlights

- **A box the operating system enforces.** Code your agent writes runs with no network, not even 127.0.0.1, and one writable folder. It can't see your home folder, your keys or the rest of your disk. Seatbelt on macOS, bubblewrap on Linux.
- **Proven, not assumed.** Before its first run, the box is tested on your machine. A script inside it tries seven ways to leak. If any works, or the result is unclear, nothing runs and you're told why.
- **Keys stay in the harness.** The box never sees them. Each key goes only to the hosts your rules name, over https.
- **A yes for the exact thing.** Sending, paying, deleting and posting wait for your approval. The approval is bound to the exact action and its arguments, works once, and expires.
- **One rules file, reviewed.** `agentfence diff old new` names every way a change widens access: a new host, a new folder, a key going somewhere new, an approval removed.
- **A log you can check.** Every run, check, approval and outbound call is written to a hash-chained file that shows edits.

```sh
pip install git+https://github.com/vn-envy/agentfence@v0.1.0
agentfence init && agentfence check
```

## Tested on

| | Python 3.11 | Python 3.13 |
| --- | :-: | :-: |
| macOS (Seatbelt), GitHub `macos-latest` | passing | passing |
| Linux (bubblewrap), GitHub `ubuntu-latest` | passing | passing |

Each run proves the box, runs 55 tests (including code run inside the real box on each OS), and runs the example harness end to end.

## Worth knowing

- **Harness bugs are as real as box bugs.** A sandbox fences the code, not the process that reads its output. agentfence reads output through pipes, kills the whole process group when a run ends, and removes any link the code leaves before anything reads its folder. [The architecture doc](https://github.com/vn-envy/agentfence/blob/v0.1.0/docs/ARCHITECTURE.md#the-box) explains each.
- **macOS needed a rule we didn't expect.** On real macOS machines, every process reads the root folder `/` itself as it starts, so a deny-by-default profile stops even `/usr/bin/true`. The profile allows exactly `/` and nothing beneath it. [The Seatbelt profile](https://github.com/vn-envy/agentfence/blob/v0.1.0/docs/ARCHITECTURE.md#the-seatbelt-profile) explains every line.
- **Limits.**
  - agentfence doesn't defend against kernel exploits or a hostile local user.
  - Approvals live in memory.
  - The log can't show lines cut off its end.
  - Windows isn't supported.
